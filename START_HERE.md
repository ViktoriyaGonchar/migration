# С чего начать (для новичка)

Этот файл — **короткая дорожка**: как запустить проект у себя и убедиться, что он живой. Подробности, безопасность и прод — в [README.md](README.md), [DEPLOY.md](DEPLOY.md) и [TESTING.md](TESTING.md). Их не нужно читать целиком, чтобы просто попробовать.

---

## Что это за проект простыми словами

Сайт с закрытыми страницами: зайти можно по специальной ссылке после оплаты/выдачи доступа. Рядом — **админка** в браузере (очередь ручных заявок на оплату, кнопки согласования). Ещё есть **Telegram-бот**: реквизиты, заявки, статусы. Всё это смотрит в одну **базу SQLite** на компьютере (или в контейнере).

**Важно без путаницы:** «одобрить заявку» в админке **не то же самое**, что «выдать доступ» — доступ выдаётся отдельным шагом (оператор / отдельные действия). Здесь это только зафиксировано, чтобы ты не ждал «магии» после кнопки в очереди.

---

## Из чего он состоит

| Часть | Зачем |
|--------|--------|
| **app** (FastAPI) | Сайт, вход по ссылке, админка, внутренний API для бота |
| **bot** | Telegram: команды, оплата, уведомления |
| **База (SQLite)** | Хранит пользователей, заявки, подписки |

Бот **не открывает файл базы сам**. Он ходит в **app** по HTTP (локально по умолчанию `http://127.0.0.1:8000`, в Docker адрес задаётся в `docker-compose.yml`) и передаёт ключ `INTERNAL_API_KEY`. В Docker база лежит только у контейнера **app** — так и задумано.

## Что нужно перед запуском

1. **Python 3.11 или новее** — установлен на системе.
2. Папка проекта скачана / клонирована.
3. Файл настроек: скопируй [.env.example](.env.example) → `.env`. Для prod, оплаты и тонкой настройки смотри [.env.full.example](.env.full.example) (для первого раза не обязателен).

## Где взять и как сгенерировать значения для `.env`

Кратко: случайные секреты — командами ниже (каждый раз новая строка); токен бота — у BotFather; **`.env` в git не коммитить** (файл в `.gitignore`). **Не клади одну и ту же** случайную строку в `TOKEN_PEPPER`, `ADMIN_SESSION_SECRET` и `INTERNAL_API_KEY` — для каждой переменной своё значение.

Случайная строка (запусти несколько раз, вставь **разные** результаты в `.env`):

```bash
python -c "import secrets; print(secrets.token_urlsafe(32))"
```

или:

```bash
openssl rand -hex 32
```

| Переменная | Откуда значение |
|------------|-----------------|
| **TOKEN_PEPPER** | Секрет **приложения** для одноразовых токенов входа на сайт (хэши). Нужна **длинная случайная** строка — сгенерируй командой выше. |
| **ADMIN_SESSION_SECRET** | **Отдельный** секрет только для cookie-сессии админки `/admin`. **Не** подставляй сюда `TOKEN_PEPPER` — сгенерируй другую строку той же командой. |
| **INTERNAL_API_KEY** | Общий секрет заголовка `X-Internal-Key` для **app и бота**: **одно и то же** значение в `.env` (оба процесса читают один файл или одинаковые переменные в compose). Сгенерируй **третью** новую строку, не совпадающую с двумя предыдущими. |
| **BOT_TOKEN** | Только из Telegram: [@BotFather](https://t.me/BotFather) → `/newbot` или существующий бот → токен **HTTP API** (вид `123456:ABC...`). |
| **BOT_USERNAME** | Имя бота **без** `@` (как в настройках бота в BotFather). Для **обычного старта** процесса бота **не обязателен**; нужен для deep link, `mc-cli issue-telegram-link` и ссылок в админке (Operator). |

## Вариант 1: локальный запуск без Docker

**Идея:** на своём компьютере поднять сайт и бота двумя терминалами.

### Шаг 1 — настройка окружения

Скопируй пример настроек в рабочий файл (в корне проекта):

```bash
copy .env.example .env
```

На Linux/macOS вместо `copy` обычно:

```bash
cp .env.example .env
```

Открой `.env` и заполни поля так же, как в таблице раздела **«Где взять и как сгенерировать значения для `.env`»** выше:

- **Всегда:** `TOKEN_PEPPER` (секрет для входа на сайт) и `ADMIN_SESSION_SECRET` (отдельный секрет для админки) — две **разные** сгенерированные строки.
- **Если запускаешь бота:** `BOT_TOKEN` у BotFather и `INTERNAL_API_KEY` — **третья** новая сгенерированная строка; это значение одно и то же для app и бота в одном `.env`.
- **`BOT_USERNAME`** для старта бота не нужен; реквизиты `/pay` и остальное — по желанию, см. [.env.full.example](.env.full.example).

Локально URL к API для бота уже по умолчанию `http://127.0.0.1:8000` (см. `bot/config.py`); в Docker его задаёт compose — в минимальный `.env` не дублируй.

### Шаг 2 — установка зависимостей

В корне проекта, в виртуальном окружении (если пользуешься venv — активируй его):

```bash
pip install -e .
```

**Что должно получиться:** команды `mc-cli` и `mc-bot` становятся доступны в этом окружении.

### Шаг 3 — база данных

```bash
alembic upgrade head
```

**Зачем:** создаётся структура таблиц. Если `DATABASE_URL` не задан в `.env`, используется путь по умолчанию `./app.db` (см. `app/config.py`).

### Шаг 4 — первый администратор админки

```bash
mc-cli create-admin --email твой@email --password твой_пароль
```

Подставь свой email и пароль. **Ожидание:** в консоли появится сообщение с id админа.

### Шаг 5 — запуск сайта (backend)

```bash
uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

Оставь это окно открытым. **Проверка:** в браузере открой `http://127.0.0.1:8000/health` — должен быть ответ вроде `{"status":"ok"}`.

### Шаг 6 — запуск бота

Новый терминал, тот же корень проекта, тот же `.env`:

```bash
mc-bot
```

**Ожидание:** в логах нет постоянных ошибок про 401/503 к API; в Telegram бот отвечает на `/start` (если токен верный).

### Шаг 7 — быстрая проверка вручную

- **Сайт:** `http://127.0.0.1:8000/health` — ок.
- **Админка:** `http://127.0.0.1:8000/admin` — форма входа; войди под email/паролем из шага 4.
- **Бот:** напиши боту в Telegram — не должно «висеть» без ответа при корректном токене.

Дальше — сценарии из [TESTING.md](TESTING.md), если нужно глубже.

## Вариант 2: запуск через Docker Compose

**Идея:** приложение и бот в контейнерах; база в томе у **app**; бот стучится в **app** по внутреннему адресу. Ты не публикуешь порт приложения в интернет — только на своём ПК для проверки compose сам по себе порт наружу не пробрасывает (см. [docker-compose.yml](docker-compose.yml)).

### Шаг 1 — `.env`

Файл `.env` в корне **обязателен** для compose (скопируй из `.env.example`). Минимальный пример **не** содержит `DATABASE_URL` и `INTERNAL_API_BASE_URL`: их для контейнеров задаёт [`docker-compose.yml`](docker-compose.yml) (`DATABASE_URL` у `app`/`migrate`, `INTERNAL_API_BASE_URL=http://app:8000` у `bot`). Не дублируй их в `.env` без необходимости.

Для **production** добавь в `.env` из [.env.full.example](.env.full.example) как минимум `BASE_URL` и `COOKIE_SECURE=true` под HTTPS.

### Шаг 2 — сборка образов

```bash
docker compose build
```

**Ожидание:** сборка `app` и `bot` завершается без ошибки.

### Шаг 3 — миграции (один раз перед первым запуском или после обновления кода)

```bash
docker compose --profile migrate run --rm migrate
```

**Зачем:** применить схему Alembic к базе в томе. Делай до того, как пойдут пользователи/бот всерьёз.

### Шаг 4 — запуск app и bot

```bash
docker compose up -d app bot
```

### Шаг 5 — статус и логи

```bash
docker compose ps
```

У сервиса `app` в колонке health обычно ждут `healthy`.

```bash
docker compose logs -f app
```

В другом окне при необходимости:

```bash
docker compose logs -f bot
```

**Ctrl+C** только выходит из просмотра логов, контейнеры не обязаны остановиться.

### Шаг 6 — что проверить после старта

Порт **8000** снаружи хоста compose **не обязан** быть открыт — это нормально. Проверка изнутри:

```bash
docker compose exec app python -c "import urllib.request; print(urllib.request.urlopen('http://127.0.0.1:8000/health').read())"
```

Должен появиться ответ со `status` и `ok`. Бот — в Telegram, как в локальном варианте.

На **настоящем сервере** с доменом сайт обычно открывают через **reverse proxy** (единственная точка входа из интернета); приложение за прокси не вывешивают напрямую в WAN. Кратко это описано в [DEPLOY.md](DEPLOY.md) и комментариях в `docker-compose.yml`.

## Минимальный ручной smoke test

1. `/health` — отвечает «живой».  
2. `/admin` — открывается, логин работает.  
3. Бот в Telegram — отвечает, нет вечной ошибки связи с API.  
4. Если включались платежи/заявки — в админке видна очередь (детали — [TESTING.md](TESTING.md)).

## Самые частые ошибки новичка

| Симптом | Что часто не так |
|--------|-------------------|
| Бот «молчит» или ругается на API | Пустой или разный `INTERNAL_API_KEY`; не запущен app; локально URL по умолчанию `127.0.0.1:8000`, в Docker задаётся compose. |
| Internal «выключен» (503) | В `.env` не задан `INTERNAL_API_KEY` у приложения. |
| Не пускает в админку | Не создан админ `mc-cli create-admin` или неверный пароль. |
| Ссылки входа ведут не туда | В проде не совпадает **`BASE_URL`** с реальным адресом сайта в браузере. |
| После HTTPS куки не держатся | Не выставлен `COOKIE_SECURE=true` при работе по https. |
| Две копии app с одной SQLite | Так делать нельзя: одна база — один writer (один процесс app / без нескольких workers на один файл). |

Не путай: **`BASE_URL`** — для ссылок в браузере (задаётся в `.env` для prod, см. `.env.full.example`). Адрес API для бота локально — дефолт в коде; в Docker — из `docker-compose.yml`, не из минимального `.env.example`.

## Как выглядит первый простой «production-like» deploy

Коротко, без теории:

1. Сервер с Docker (или аналог) и доменом.  
2. **Только reverse proxy** смотрит в интернет (HTTPS). Прокси перенаправляет запросы на контейнер **app** по внутренней сети. **Не** выставляй порт приложения напрямую в WAN.  
3. В `.env` на сервере: секреты из минимума + из [.env.full.example](.env.full.example) — **`BASE_URL=https://твой-домен`**, **`COOKIE_SECURE=true`**, одинаковый **`INTERNAL_API_KEY`** для app и bot.  
4. Собрать образы, выполнить **migrate**, поднять **app** и **bot**, проверить `/health` и логи.  
5. Проверить вход по ссылке и админку в браузере уже **через домен**.

Подробный чеклист — [DEPLOY.md](DEPLOY.md).

## Если всё не работает, проверь сначала

1. **`.env`** — файл есть, не пустой, значения без лишних пробелов в конце строки с ключом.  
2. **`INTERNAL_API_KEY`** — задан у приложения и совпадает с тем, что использует бот.  
3. **`INTERNAL_API_BASE_URL`** — локально по умолчанию в `bot/config.py`; в Docker задан в compose. Меняй только если нестандартный порт/сеть.  
4. **Миграции** — выполнен `alembic upgrade head` (или `docker compose --profile migrate run --rm migrate`).  
5. **`/health`** — отвечает, когда app запущен.  
6. **Логи** — `docker compose logs app bot` или консоль uvicorn / mc-bot.  
7. **`BASE_URL` и `COOKIE_SECURE`** — согласованы с тем, как ты открываешь сайт (http/https).  
8. **`BOT_TOKEN`** — верный, бот в Telegram не «другой бот».

Удачи. Если застрял — опиши симптом и что уже сделал по списку выше; с техническими деталями помогут [TESTING.md](TESTING.md) и [DEPLOY.md](DEPLOY.md).
